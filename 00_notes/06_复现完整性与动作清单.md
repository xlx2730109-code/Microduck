## B. “摔倒站起”具体指什么

| 概念 | 所在模型/代码 | 能确认什么 | 不能由此推出什么 |
|---|---|---|---|
| 坐下后站起 | sitstand | 有对应权重 | 侧躺、趴倒、仰倒都能恢复 |
| 普通脚底倒地恢复 | walk的VelStand联合策略 | manifest明确描述行走、保持和倒地恢复，runtime也保留联合恢复路径 | 任意地面、任意倒姿、带任何配件均可靠起身 |
| 轮滑倒地起身 | roller/standup | 有独立权重 | 换普通脚掌直接运行 |
| `microduck_standup_env_cfg.py` | 上游训练任务 | 其初始说明主要是坐姿到站姿，含后续训练机制 | 文件名有StandUp就表示本机HD1910任意倒地任务已适配 |
| 摔倒不自动卸力 | 镜像默认行为 | 倒地后不会自动关扭矩 | 模型没有恢复能力；两者不是同一功能 |

普通脚底联合模型证据：`models/1cbf…/manifest.json`的`name="velstand"`、`description`和`task="Mjlab-VelStand-Rough-Backlash-MicroDuck"`；其`model-info.json`写“行走＋倒地联合9600轮”。runtime的`robotd/src/selftrained_checks.rs`保留“fall recovery belongs to the same walk model”检查。

建议验收顺序：

1. 完成常规站立、低速行走、停止和卸力。
2. 备份已通过的首走配置，在承托与可立即卸力的条件下设计恢复试验。
3. 分别记录侧倾/趴倒/仰倒等实际起始姿态，不能只成功一次就扩大为全部倒姿。
4. 成功记录包含恢复时间、是否借头部接地、是否顶限位、电压及能否立即停止。
5. 失败先卸力并保留视频/诊断，不连续摔落试验或先改大增益。
6. 起身后再次验证零命令保持和停止。轮滑另行装配、定版和验收。

当前没有执行上述试验，不提供“已经保证会自动起来”的结论。

## C. 训练资料到底齐到哪一层

| 层次 | 本地内容 | 状态 |
|---|---|---|
| 当前fanhao训练工程 | `software/training/`，包括源码、MJCF/网格、HD1910 M6参数、锁文件、测试和导出 | 文件齐，未装环境/未执行 |
| 当前可视化训练台 | `software/training-studio/` | 真实训练/演示分开，未执行 |
| HD1910明确任务 | `Mjlab-Velocity-Flat-MicroDuck-HD1910`、Rough同类、`Mjlab-Balance-Flat-MicroDuck-HD1910` | 已注册不等于全动作真机通过 |
| 上游其他动作任务 | VelStand、SitStand、捡物、踢球、翻滚、轮滑等 | 源码存在，不能自动视作全部HD1910训练入口 |
| 模型标注上游提交 | `03_official/microduck_rl_8d0db749/` | 241个文件已核验，保留原始代码 |
| 配套训练中控适配代码 | 当前runtime快照`microduck-hd1910/training-console/` | 作为模型导出/任务适配参考，不切换本次主控路线 |
| 成品模型的参数与合同 | 独立模型目录内现有JSON/TOML和原始导出记录 | 保留源包原样，不拼接不同模型 |
| 原作者完整检查点与优化器 | 这10个模型对应PT | 本地未取得，不能从作者第9599轮直接续训 |
| 第三方库和GPU环境 | uv锁定依赖、PyTorch/mjlab/BAM等 | 需要联网安装及实际GPU短测 |

因此“复现成品动作”与“重新训练出同等效果”是两个任务。前者使用当前模型并做本机验收；后者需要重建环境、对齐执行器与动作合同，再训练评估。元数据里指向作者电脑的`model_9599.pt`路径不是该文件已经在本地。

## D. Windows如何训练

| 方案 | 是否采用 | 理由 |
|---|---|---|
| Windows＋WSL2 Ubuntu＋NVIDIA GPU | **本机优先候选** | 无需重装或双系统，训练使用Linux依赖 |
| 原生Ubuntu＋NVIDIA GPU | 可用 | 适合现有Linux训练机 |
| Windows原生终端直接跑当前工程 | 不作为本项目已验证路径 | 锁定依赖、仿真和脚本按Linux/WSL整理 |
| 没有兼容CUDA显卡的电脑 | 可管理远程GPU训练 | 浏览器/SSH管理，不强行用当前CUDA工程跑AMD/核显 |

具体步骤见 [训练迁移指南B节](08_训练导出与迁移指南.md#b-训练电脑准备)。此次只读系统检查结果与环境安装状态分开记录，没有开启系统功能、安装驱动或安装WSL。

本机已读到RTX5080、16303MiB显存，WSL列表查询12秒超时，安装状态待核；原始字段记录在environment-check.json。后续先核对已有WSL，不因超时就重装或重置Ubuntu。

## E. 还剩什么，不写成“全都齐了”

1. 根据最终主控/HAT/IMU实物，冻结逐针接线、固件和已测组合。
2. GPU环境安装与短测；第三方依赖没有做完整离线包。
3. 作者未取得的PT检查点不能补造；需要时从头训练或取得合法公开检查点。
4. 自然对话的声卡、云激活、实体触发、自启动和并发仍需集成。
5. 所有动作的本机标定与分级验收，尤其普通脚底倒地恢复和轮滑。
6. 视频第7/8集与部分实物资料缺口仍按原待办保留，不将链接当本地视频文件。

源码、成品权重、公开配置齐全是实施基础；不是“所有公开/未公开资源都已离线封装”或“本机已经完成全部功能”的证明。
