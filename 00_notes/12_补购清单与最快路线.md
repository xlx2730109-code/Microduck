## 推荐组合

**运动主线：Radxa ZERO 3W + kissqy 配套 AMP2.0 HAT/FT6 IMU 成品 + R1/control.43/V167 + 本机标定。** 摄像头采用该复刻已有资料的 Radxa 8M219。语音先复用 HAT 音频输入输出，在本机运行 Linux 云端语音客户端，避免更换整机计算平台。

这条运动组合有社区作者实机记录。**自然对话客户端与 Microduck 的集成尚未在本机验证**，不能把“买齐零件”写成“刷卡后全部功能直接可用”。

## 自然对话：软件路线与硬件边界

| 方案 | 已找到的能力 | 当前判断 |
|---|---|---|
| Linux Rust 小智客户端 | [xiaozhi_linux_rs](https://github.com/haoyn231/xiaozhi_linux_rs)：AArch64、无界面运行、ALSA 录放音、云端 STT/TTS/WebSocket、MCP | 适合先核对轻量板端对话；作者没有列 Radxa ZERO 3W＋本 HAT 的实测，也不内置离线唤醒/AEC |
| Python 小智客户端 | [py-xiaozhi](https://github.com/huangjunsen0406/py-xiaozhi)：ARM/Linux、CLI、视觉工具与离线唤醒 | 备选；README 推荐内存至少 4GB，不能未经实测就承诺本机 2GB 全功能运行 |
| 独立 ESP32-S3 小智音频模块 | [xiaozhi-esp32](https://github.com/78/xiaozhi-esp32)：云端语音、部分板卡支持 AEC/唤醒/摄像头 | 后备方案；若需要则买已适配完整成品，增加板卡前先核对尺寸、重量、供电和麦克风/喇叭占用，不先堆板 |
| DuckBuddy | [项目](https://github.com/Animan-AI/DuckBuddy)：离线语音识别/视觉/行为集成参考 | 用不同主控和 HL-2915，不直接覆盖本机 HD-1910 运动固件 |

自然对话第一轮验收顺序：HAT 录音 → 播放 → 本机云端对话 → 回声/打断与唤醒 → 摄像头出图 → 需要时让对话调用相机。**能看视频和能理解画面是两个功能**，视觉问答需额外接入相机工具与支持图像的云模型。

运动仍由原 `robotd` 管理，语音进程不得直接写舵机总线。需要语音动作时，通过受限接口请求已验证动作；手柄与停止控制优先。本轮没有编写或部署该集成。

## 最快实施顺序

1. 并行准备电控成套件、电池与存储、相机/音频、工具。先向同一卖家确认接口与打印适配，减少跨店板卡版本组合。
2. 到货后在桌面先测主控启动、相机、录放音和总线身份；这些可在机械装配完成前核对。
3. 按既定飞特方案完成舵机与 IMU 本机标定、架空 HOME/卸力，再做短时首走。
4. 云端对话独立进程接入，不改动已通过的运动控制基线；先完成自然对话，再接图像工具与语音动作。
5. 保存能复现的固件/镜像/模型/标定/接线及实物照片。交付物以本机验证结果更新，不以商品宣传推定通过。

没有给出“几天必定完成”的承诺：发货、打印件版本、成品板兼容、音频全双工和语音集成是实际工期变量。优先成品和单一配套路线，是本轮减少这些变量的措施。
