目标：在首走基线之后，完成可追溯的 HD1910 仿真训练、模型评估、导出、部署与恢复。

| 需求 | 采用入口 | 现在是否要做 |
|---|---|---|
| 尽快让小鸭走 | 镜像配套模型，见 [执行指南](02_分阶段复现指南.md) | 先做，不要求训练 |
| 理解训练过程 | 本文 A–C、作者 Training Studio | 首走后安排 |
| 修改步态 | HD1910 平地任务，真实 GPU 训练 | 仿真参数与硬件合同核对后 |
| 将模型移上机 | 本文 D–E、机器人 Studio“模型管理” | 仿真评估通过后 |
| 换电脑/云服务器/卡 | 本文 F–G | 迁移前先备份 |

**本项目尚未安装训练环境、跑 GPU 实验或生成本机权重。** 下列命令没有执行。实验和正式代码修改继续遵守用户的先验证规则。

## A. 三个软件对象分开理解

| 名称 | 在哪里运行 | 地址/作用 |
|---|---|---|
| 机器人 Studio | ZERO 主控，镜像自带 | `:8000`；标定、手柄、运行模型与诊断 |
| Training Studio | Linux/WSL2 NVIDIA GPU 电脑或服务器 | 默认 `127.0.0.1:8093`；调度训练、评估和导出 |
| mjlab 训练引擎 | 同一训练执行端 | 实际计算仿真与 PPO，保存 PT 检查点 |

Training Studio 的演示模式生成合成指标和示意回放，不产生可部署权重。界面显示百分比是迭代进度，不表示“已学会走路”。已有 ONNX 推理模型通常不能直接恢复优化器继续训练；续训需要适用的完整 PT 检查点。

源码固定于 [本地训练工程](../02_feetech/microduck-replica_20261024/software/training/README.md)和 [训练台](../02_feetech/microduck-replica_20261024/software/training-studio/README.md)。不用旧 V167 训练中控的菜单替代当前 Training Studio。

## B. 训练电脑准备

**Windows可以继续用：优先Windows＋WSL2中的Ubuntu＋NVIDIA GPU，不需要重装系统或双系统。** 当前工程按Linux/WSL2准备，原生Windows终端不作为已验证训练路径。Windows负责日常操作、写卡和浏览器；WSL内运行Python/uv、仿真和训练台；ZERO只执行导出的模型。

**“不用Ubuntu”与“完全不用Linux”须分开。** 仅使用现成模型复刻时，电脑端可全程Windows，机器人运行已提供的Linux镜像，不需要先搭训练环境。自己训练时，Ubuntu不是唯一Linux发行版；但本项目当前按Linux/WSL2准备。若不在本机使用WSL，可由Windows通过浏览器/SSH管理远程Linux GPU训练端。纯Windows原生需要独立兼容性验证，不能将其列为当前已通过路径，也不能声称技术上绝对不可能。

上游mjlab公开FAQ说明Windows/WSL做过初步测试、部分流程不保证稳定；其主开发平台为Linux。该上游说明不是本机锁定版本和整套Microduck依赖已通过的证明。依据：[mjlab公开FAQ](https://mujocolab.github.io/mjlab/v1.6.0/source/faq.html)。本次没有进行Windows原生安装、适配或训练。

| Windows训练准备顺序 | 检查与边界 |
|---|---|
| 1. 确认显卡与Windows版本 | 记录NVIDIA型号、显存和驱动；未读到设备信息不推定没有显卡 |
| 2. 检查是否已有WSL2/Ubuntu | 先只读列发行版；已有环境先复用核对，不重复安装或重置 |
| 3. 必要时准备WSL2 Ubuntu | 缺少才按微软流程安装，涉及系统功能/重启时另行安排；本轮未安装 |
| 4. 在WSL验证GPU | 进入Ubuntu执行nvidia-smi，再安装锁定训练环境 |
| 5. 独立工作副本短测 | 不改本地归档源码；按下文64环境/5轮入口小规模验证 |

WSL使用Windows宿主机的NVIDIA驱动；不要在WSL中另装Linux显示驱动覆盖它。完整CUDA Toolkit是否需要，由实际锁定依赖和编译需求决定，不先叠装多套工具链。依据：[微软CUDA on WSL](https://learn.microsoft.com/en-us/windows/ai/directml/gpu-cuda-in-wsl)、[NVIDIA WSL指南](https://docs.nvidia.com/cuda/wsl-user-guide/index.html)。

Windows只读查看已有WSL发行版：

```powershell
wsl --list --verbose
```

**本机只读检查，2026-10-24：** `nvidia-smi`读取到NVIDIA GeForce RTX 5080、16303MiB显存、驱动610.47。WSL发行版查询12秒超时，不能据此认定已安装或未安装Ubuntu；本轮没有安装驱动、启用系统功能或重置WSL。该显卡是训练准备条件，不等于已完成mjlab/CUDA短测。

| 检查项 | 要求/做法 |
|---|---|
| 系统 | Linux 或已正确配置 GPU 的 WSL2；不能在普通 Windows 终端直接照抄 Linux 命令 |
| GPU | NVIDIA CUDA 可用；先记录型号、驱动和显存，不先承诺某个并行环境数 |
| 工具 | Git、uv；Python 3.12 和锁定依赖由 `uv sync` 准备 |
| 工作目录 | 独立可写工作副本，不能在已归档的资料快照内直接跑实验 |
| 短测输出 | Windows/WSL 对应 `E:\HuanCun\AI_tmp\GPT\tmp_20261024_microduck_training`；远端位置执行前另行明确 |
| 正式训练结果 | 用户确认后使用独立实验目录，保留源码提交、配置、日志和完整检查点 |

## C. 用可视化训练台执行

在训练引擎目录转到相邻训练台。

```bash
cd ../training-studio
```

使用训练环境中的 Python 启动真实模式。

```bash
../training/.venv/bin/python run.py
```

在服务所在机器打开 `http://127.0.0.1:8093/`。远程服务器通过 SSH 转发到本机；下面用户名和主机是占位符。

```bash
ssh -N -L 8093:127.0.0.1:8093 USER@GPU_HOST
```

操作顺序：

1. 进入“计算环境”，确认 GPU、MuJoCo 图形后端、mjlab 1.3.0、CUDA 和 HD1910 注册检查通过。
2. 新建“HD1910 平地行走”，保留配置快照和种子，不选 XL330、轮滑或单脚平衡作为首个任务。
3. 按作者入口先做 **64 环境、5 轮**短试跑。它只检查加载、物理步进、保存与评估链路；执行预算先设短超时，超时记录现象后再决定是否延长。
4. 短测检查：数值有限，无 NaN/Inf；正确保存 PT；评估视频对应所选检查点；不是演示模式。
5. 报告短测配置、输出与问题，获用户确认后再正式训练；5 轮权重不用于真机行走。
6. 正式训练前核对质量/惯量、动作系数、默认姿态、执行器、随机化和命令范围，保持 HD1910 独立任务，不修改共享官方任务。
7. 正式训练放大环境数和轮数时以显存和实际迭代耗时为依据，不盲目照抄大卡参数。
8. 选检查点评估零命令、前后、转向、起停和失败场景；保留成功、失败及对照条件。
9. 比较同任务和同模式实验，确定候选后导出。

本版 Training Studio：关网页不停止任务，**关闭训练台服务会停止它拥有的子进程**。暂停仍占显存；不会停止云主机计费。长训练应使用经确认的终端会话/服务管理方案保持服务运行。

### C1. 不用界面时的命令行入口

先确保工作副本和短测输出位置已经核对，再在 `software/training/` 使用作者短测命令：

```bash
uv run --frozen train Mjlab-Velocity-Flat-MicroDuck-HD1910 --env.scene.num-envs 64 --agent.max-iterations 5 --agent.logger tensorboard
```

默认会在工作副本 `logs/rsl_rl/microduck_hd1910_velocity/` 生成文件；使用临时短测时，工作副本/输出应置于用户规定的临时任务目录，不能污染原始快照。

## D. 导出与仿真验证

### D1. 需要保留哪些成果

| 文件/记录 | 用途 |
|---|---|
| 完整 PT 检查点 | 评估、可能的续训；是否含优化器等状态须检查 |
| `policy.onnx` | ZERO 推理 |
| `manifest.json`、`deployment-contract.json` | 模型身份、关节、观测、动作与运行要求 |
| 其他导出配置/执行信息 | 同次导出若有 `deployment-execution.json`、`deployment-runtime.json`、`model-info.json` 等一并保留 |
| 源码提交、锁文件、参数和种子 | 重建训练与解释差异 |
| 评估视频和数值对照 | 证明候选通过了哪些检查，保留失败场景 |

在引擎目录先查实际导出参数：

```bash
uv run --frozen python scripts/export.py Mjlab-Velocity-Flat-MicroDuck-HD1910 --help
```

以下路径须替换为同一次实验真实检查点和新的候选文件；不覆盖已验收模型。

```bash
uv run --frozen python scripts/export.py Mjlab-Velocity-Flat-MicroDuck-HD1910 --checkpoint-file /absolute/path/model_XXXX.pt --onnx-file /absolute/path/candidate.onnx
```

导出脚本包含观测归一化；仍要核对具体包，不在运行端重复归一化。命令行导出单个 ONNX 不保证已产生机器人 Studio 所需的全部元数据；缺少合同不能随意补名、改后缀或塞入另一次实验的 JSON。

### D2. 导出后再验什么

1. 对相同观测比较 PT 与 ONNX 输出；记录容差和不能解释的差异。
2. 用匹配 HD1910 执行器的仿真检查静止、前后、转向与停止，不将保留 XL330 执行器路径的独立测试脚本直接当作 HD1910 通过证明。
3. 核对当前常用 61 维观测、14 维动作和 50Hz 的每一维语义；同维度不意味着同任务，单脚平衡的命令定义不同。
4. 对照实机的关节顺序、零位、方向、默认站姿、动作缩放、滤波、舵机增益及时间步。
5. 保存所有成果和 SHA256，候选未通过时保留失败记录，不替换旧基线。

## E. 导入小鸭并逐级验收

依据：[作者模型导入说明](../02_feetech/microduck-replica_20261024/software/studio/MODEL_IMPORT.md)。

1. 先备份旧配置、标定、模型和可启动系统卡，记下恢复方式。
2. 将同次导出的 `policy.onnx`、`manifest.json`、`deployment-contract.json` 及可用的其他运行元数据置于单一模型目录，打成 ZIP/tar.gz/tgz；不混多个模型或训练日志。
3. 部署包压缩上限 64MiB、展开上限 256MiB。进入机器人 Studio `:8000` 的“模型管理”导入。
4. 导入通过只表示安装成功；预检失败先读合同/运行端不兼容原因，不能强制复制覆盖系统模型。
5. 卸力后选择正确用途，点击“使用此模型”，等主程序确认实际路径。
6. 基础站姿、P 参数或关节顺序不同不能直接热切换，需要部署适配。
7. 重新完成架空、小幅保持、卸力、低速落地与停止验证，再做带摄像头/语音并发。
8. 异常先恢复旧模型及对应参数；只换回 ONNX 而不恢复参数可能仍然异常。

## F. 换电脑、换服务器、换主控

| 场景 | 要复制 | 在新环境做什么 |
|---|---|---|
| 换训练电脑 | 固定源码/锁文件、两个结果目录、完整 PT、配置及评估 | 重建 Python/CUDA 环境，短测后核对能否续训 |
| 本地转 GPU 服务器 | 同上，另记工作目录和路径关系 | 启动训练台并 SSH 转发，确认成果实际留在服务器 |
| 更换系统卡 | 已核验镜像、本机配置/标定、导入模型库和验收记录 | 备用卡启动，先看身份/数据，再标定检查和架空验证 |
| 更换 ZERO 主控 | 上述机器人备份及板卡/无线信息 | 先验镜像支持该批主控，再恢复本机资料 |
| 换另一只小鸭 | 可复用源码和候选模型 | 新机必须独立标定，不复制旧机零位当成新机实测 |

Training Studio 结果要同时保留 `training-studio/state/runs/` 和 `training/logs/rsl_rl/`；界面可能引用旧绝对路径，换位置后需明确恢复引用。本版没有“上传成果 ZIP 自动恢复训练”的入口。Windows 的 `.venv` 不复制到 Linux 直接用。

## G. 机器人备份和恢复卡

| 内容 | 本镜像的来源位置 | 处理 |
|---|---|---|
| 飞特配置和标定 | `/etc/robot/feetech-ft5/` | 完整备份并计算哈希；目录名沿用 ft5，不自行改名 |
| 媒体等总配置 | `/etc/robot/robotd.toml` | 保存相机等实际启用状态 |
| Studio 状态与导入模型 | 通常 `/var/lib/microduck-studio/` | 按实际 state 路径确认，保留导入身份与配置 |
| 默认 runtime 和模型 | `/opt/robot/feetech-ft5-r5/` | 发布版本和文件身份与系统卡一同记录 |
| 对话客户端 | 最终安装目录及设备配置 | 备份配置结构；凭据单独保管，不放公开资料包 |
| 系统卡 | 关机后整卡读出的镜像 | 使用明确支持读卡备份的工具；不要用 Flash 写入代替读出 |

制作恢复卡时先正常关机、断电取 A 卡，再通过已核对的工具读出完整卡镜像；使用 Etcher 将备份写入 B 卡。标称同为128GB的卡实际扇区数可能不同，目标小于源整卡镜像时不能强行写入，需调整镜像或使用更大实际容量卡。

恢复验收顺序：B卡启动 → 核对版本和实际本机标定 → 检查舵机/IMU → 卸力/保持 → 低速首走。只成功写卡、复制文件或显示页面不算恢复验证通过。

## H. 已知边界

- 训练工程沿用上游几何质量/惯量及公开 BAM M6 执行器参数，不是本机辨识结果。
- 作者 GPU 短试跑不等于长训练完成，也不等于该权重已在本机稳定行走。
- 内置运动模型、源码和网格的许可范围不同，按原文保留；本次定位个人复刻。
- 先形成普通脚底基线，再引入新动作或结构变化，避免同时修改机械、标定和模型而无法定位问题。
