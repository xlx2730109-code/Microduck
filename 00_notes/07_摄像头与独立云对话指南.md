# 摄像头与独立云对话
目标：在 fanhao 运动系统上增加真实摄像头和自然问答，整机运行时不依赖电脑，允许通过 Wi-Fi 调用云端 AI。

| 功能 | 项目现状 | 首版通过标准 |
|---|---|---|
| 运动 | 使用 fanhao HD1910 镜像与模型 | 独立遥控行走，按执行指南验收 |
| 摄像头 | 镜像默认测试画面 | 出现真实场景，遮挡/移动相机时画面对应变化 |
| 麦克风/喇叭 | HAT 配套，实物未购 | 单独录音和播放清楚、不过载 |
| 自然问答 | 需要另装板端客户端 | 无调试电脑参与，语音提问并听到连贯回答 |
| 并发 | 尚未测试 | 相机/对话工作时，运动控制和供电仍稳定 |
| 看图回答/语音动作 | 额外扩展 | 有明确工具和权限映射后另验，不由预览自动获得 |

本指南是待实施方案，没有宣称存在适配本机的一键对话固件。相机、声卡和板端客户端的最后配置依赖实际 HAT/主控版本，不编造已经通过的设备名称。

## A. 先把硬件配对

| 模块 | 采用方向 | 需要确认 |
|---|---|---|
| 相机 | Radxa Camera 8M 219 / Sony IMX219 | 板型、镜头高度、面板孔位与 ZERO 驱动 |
| FPC | ZERO 3W 对应 22Pin/0.5mm → 15Pin/1.0mm 同面版本 | 接头触点方向、长度和卡扣；相机与 ZERO 都在头内 |
| 麦克风 | 先用 HAT 已包含的模拟麦克风 | HAT 实际 codec、拾音孔、是否已装及录音测试 |
| 扬声器 | 按 HAT 功放配套的 3525 腔体款 | 阻抗、功率、接头和固定空间，不按另一个 HAT 的 HP1.25 推定 |
| 网络 | 小鸭接入可上网 Wi-Fi | 云域名连通、账户/设备绑定、时间和证书正常 |

先不为语音另买大阵列或 ESP32 板。只有 HAT 音频或回声处理实际不满足要求时，再比较可安装的音频前端。芯片性能高不能代替空间、声学和播放参考链路验证。

## B. 摄像头从测试图切到实采

1. 关机断电后安装 FPC；核对插座触点朝向，不带电拔插。
2. 启动并进入 Studio，先观察默认画面。彩条/测试图不能证明相机已接通。
3. 如需 SSH，先在 Studio“更多”设置网页登录密码，再启用 SSH 并设置自己的 SSH 密码。
4. 备份 `/etc/robot/robotd.toml`，只修改其 `[media]` 段的 `source = "test"` 为 `source = "camera"`。不全局替换所有配置，也不覆盖整份文件。
5. 在小鸭 SSH 终端重启媒体服务：

```bash
sudo systemctl restart mediad
```

6. 回 Studio 检查真实画面，分别试遮挡、移动和不同光线，记录方向、延迟与服务状态。
7. 失败时先检查 FPC、供电、板型、设备树/驱动与服务日志；不直接重装运动系统。

查看媒体服务日志，供排障使用：

```bash
journalctl -u mediad -n 80 --no-pager
```

来源：[同版首次使用说明](../02_feetech/microduck-replica_20261024/software/image/烧录和第一次使用.md)。是否还需相机相关 overlay 必须结合发货主控和镜像现场确认，不能叠加早期“修复脚本”。

## C. 先验录放音，再装云对话

小鸭 SSH 终端分别列出录音和播放设备。

```bash
arecord -l
```

```bash
aplay -l
```

1. 记录声卡名称、card/device 号、驱动和当前占用者；不能将另一个开发板示例里的 `plughw:0,0` 当成本机固定值。
2. 短录音与播放分别测试，再测试全双工。诊断文件按用户临时目录规则保存；板端临时位置实际执行前明确，不覆盖项目音频。
3. 无声先查设备选择、音量、静音、麦克风偏置/接头和声卡占用。
4. 如运动媒体进程占用同一 ALSA 设备，先查功能归属并设计共享/独占方案；不直接停掉所有运动服务来解决。
5. 保存录音样本和结果。听清自己的录音以后，再排查云客户端。

## D. 板端云对话采用什么

首选候选：已归档 [xiaozhi_linux_rs](../06_voice/xiaozhi_linux_rs/README.md)，AArch64 GNU 架构。原文支持 ALSA、云端协议和无界面运行；**ZERO 3W 与本机 HAT 组合尚未验收**。

| 条件 | 实施选择 |
|---|---|
| 有匹配发布二进制 | 核对来源、版本、哈希、AArch64/GLIBC 与 `libasound` 后使用；不在 ZERO 上先编译大型工程 |
| 无兼容二进制 | 在匹配构建环境产出 AArch64 文件，再上板验证；不要直接混用 ARMv7/x86 文件 |
| 云服务 | 优先使用客户端已支持的小智服务路径，按实际提供者流程创建账户/绑定设备 |
| API/设备令牌 | 在板端私有配置中设置，记录配置项名但不把密钥写入本资料库 |
| 离线自然对话 | 不在本次范围；用户已允许云 AI |
| 唤醒与打断 | 按客户端实际能力测试；原文不能证明已具备完整离线唤醒或全套 AEC |

### D1. 先确认平台与运行库

在小鸭上查看架构：

```bash
uname -m
```

查看 GLIBC 版本；归档客户端 GNU 发布说明要求 2.28 或更新，实际下载版本仍需复核。

```bash
ldd --version
```

### D2. 配置和激活顺序

1. 选择并记录客户端固定版本，下载与机器匹配的 `aarch64-gnu` 发布物。
2. 在独立安装目录添加执行权限并前台启动；第一次运行会生成 `xiaozhi_config.json`。
3. 根据 C 节实际声卡，在该 JSON 中配置 `capture_device` 与 `playback_device`。优先使用实际可用的 ALSA 插件设备，而非猜测编号。
4. 按客户端显示的激活信息绑定到实际云账户，配置已支持的服务地址和设备参数；用真实提供者文档核实收费/额度。
5. 先做一轮短问答，再做多轮上下文、长回答、网络中断恢复、说话期间再次输入等检查。
6. 复现“启动客户端→激活→收音→收到回答→播放”的整条链路后，才进入自启动。
7. 本客户端默认配置部分在编译期嵌入；运行时可改字段按其 README 核对，不假定所有 `config.toml` 修改都可直接生效。

录放音配置示意如下，设备值是占位说明，不能原样作为本机结果：

```json
{
  "capture_device": "实际录音设备",
  "playback_device": "实际播放设备"
}
```

参考：[音频配置](../06_voice/xiaozhi_linux_rs/docs/音频设备配置说明.md)、[GUI 接口](../06_voice/xiaozhi_linux_rs/docs/GUI适配说明.md)、[MCP 功能](../06_voice/xiaozhi_linux_rs/docs/MCP功能说明.md)。

### D3. 无屏幕也能日常触发对话

核心客户端无界面运行，不等于装好后自动具备唤醒词/按键交互。前台链路通过后，核对归档 GUI/UDP 控制协议，从已支持的会话开始/停止命令中选择明确触发方式。

优先台架验证按键或轻量板端交互，再映射到实体按钮或手柄空闲键；保留运动的 Select/卸力等原有键位。该适配尚未实现，首版“无需电脑说话”验收必须包含实际触发方式，不能靠电脑终端一直输入命令。

## E. 自启动、回声与并发

| 项目 | 操作 | 通过条件 |
|---|---|---|
| 自启动 | 前台成功后再编写 systemd 服务，设置实际工作目录/配置、网络等待与重启策略 | 重启后无需电脑启动客户端 |
| 回声 | 先调音量/拾音与结构，再检查客户端/硬件的播放参考链路 | 回答播放不导致持续自问自答 |
| 资源 | 静止时开相机/语音，再低速行走；记录内存、CPU、温度、电压及控制状态 | 无异常重启、卡音、控制数据过期 |
| 网络故障 | 断网与恢复分别测试 | 对话可恢复，运动循环不等待云端响应 |
| 交互 | 先采用已确认的会话触发，再扩展唤醒与打断 | 不占用运动急停键，不凭宣传认定支持 |
| 恢复 | 原运动配置可单独恢复，语音服务能单独停用 | 调对话不破坏已通过的首走基线 |

服务文件须按已通过的实际命令生成，目前不提供填有猜测可执行文件/声卡路径的“直接安装服务”。这是等待台架验证的集成项，不是遗漏一个可以普遍照抄的安装命令。

## F. 视觉问答与动作控制边界

摄像头预览只说明有视频，云对话只说明能听说。若要“这是什么”看图回答，需要板端取一帧、压缩并接到支持图像的云工具；候选客户端提供 MCP 扩展，但不代表已有适配本机相机的工具。

语音控制动作需把有限指令映射到运行端明确支持的接口并处理当前状态，不能让云模型任意执行 shell 或直接写舵机。先保留遥控运动、自主问答这两条已明确的首版目标，视觉问答和动作扩展单列验收。

## G. 当前缺口

| 待补证据 | 影响 | 可并行做什么 |
|---|---|---|
| HAT 实物/板号/音频接口 | 声卡、麦克风、扬声器及服务配置不能最终确定 | 采购核对、机械装配、源码整理 |
| ZERO 批次和实际 RAM | 引导、无线、相机及并发余量待验 | 选择同批已测主控，准备系统卡 |
| 客户端与云账户 | 激活、费用及持续服务待确认 | 确认账户注册可用，不要求用户现在提供密钥 |
| 板端对话触发方式 | 无电脑交互尚未完成 | 核对客户端协议，台架验证后定版 |
| 本机实测 | 所有性能/稳定性未验 | 按 [记录模板](03_标定与验收记录模板.md)逐项保留结果 |
