# 建模、系统辨识、训练与部署审查
目标：明确当前Microduck仿真链与四足流程的对应关系，列出自训练到真机之间需要补齐的环节。

## 当前路线与四足路线的对应

| 四足常见步骤 | 当前Microduck主线 | 审查结论 |
|---|---|---|
| SW设计、材料/质量属性 | SW装配与制造资料，训练另有既存Microduck模型 | 机械设计存在；未证明本机SW修改自动同步进训练模型 |
| URDF→USD | MJCF/XML与网格直接用于MuJoCo/mjlab | 无需为了流程完整而添加USD转换 |
| Isaac Lab任务接入 | `mjlab_microduck`注册、机器人配置、执行器、PPO | 框架不同；关节、观测、动作、物理参数核对原则仍适用 |
| 系统辨识 | 公开1910 BAM M6参数作为执行器基线 | 尚非本机辨识；整机质量、惯量与接触还需校核 |
| Isaac→MuJoCo Sim2Sim | mjlab/MuJoCo Warp训练到独立MuJoCo/运行语义回放 | 重点是实现及控制语义一致；不应夸大成两个独立物理引擎验证 |
| Sim2Real | ONNX＋部署合同＋本机标定＋robotd运行配置 | 不能只复制一个ONNX或只核对输入输出维度 |

全目录静态扫描发现两份URDF，均位于备选项目；未发现 `.usd/.usda/.usdc`。这不构成当前主线缺件。训练目录19个XML可解析，所扫描的直接资源引用均存在；未执行MuJoCo编译加载，也未在SW打开装配验证引用。证据：[核查摘要](90_核查证据/audit_summary.json)、[XML检查](90_核查证据/xml_static.json)。

## A. 几何、质量、惯量与接触

| 对象 | 当前已有 | 仍需核查 |
|---|---|---|
| 外观与装配CAD | `01_mechanical/cad_v2.2/`、复刻CAD仓库和STEP | 轴心、间隙、脚底、电池和电控安装是否对应样机 |
| 训练MJCF | `software/training/src/mjlab_microduck/robot/microduck/` | 单位、轴向、关节顺序、限位、碰撞及初始化 |
| 质量/惯量 | MJCF及模型合同记录 | 整机、头部、电池等实际质量分配；不能把来源值写成本机测量 |
| 碰撞模型 | walk、allcollisions、backlash、rollers等变体 | 行走与倒地动作需要的接触不同，选错变体可能改变结果 |
| 足底接触 | 摩擦、接触求解等配置 | 已购防滑垫的厚度、柔性和真实地面未验证 |
| 齿隙 | 部分模型有串联被动backlash关节 | 被动关节不是额外舵机，也不增加策略动作维度 |

普通脚底成品walk合同记录总质量 `0.82 kg`，这是该模型的参数，不是咱们样机的称重结果。更换电池、镜头、板卡或增添配件会影响质量与重心，是否需要更新模型应由测量和现成策略表现决定。

需要补一张“实物零件/组件 → CAD → MJCF body → 质量/惯量来源 → 测量状态”映射表。目前没有证据表明现有SW装配可一键生成与训练完全一致的模型。

## B. 系统辨识齐到哪一步

| 层次 | 本地状态 | 后续工作 |
|---|---|---|
| 参数来源 | 有 `1910_m6.json`、来源提交、哈希与许可 | 保持归属，不写为本机自主辨识 |
| 执行器接入 | `FeetechBamActuatorCfg`使用公开模型 | 核查固件、P参数、电压、延迟和实机指令映射 |
| 台架参考 | 有单关节仿真/实物比较脚本 | 当前仍以XL330为对象，需HD1910独立适配 |
| 本机采集 | 未发现本机HD1910采集结果或接线验收 | 明确适配器、负载、采样时间、反馈字段与电压测量 |
| 参数拟合 | 不是当前项目完成的本机实验 | 确定拟合参数、约束、训练集与留出验证集 |
| 整机辨识/校核 | 没有本机称重、重心/惯量及接触闭环 | 分组件测量，并评估对策略的影响 |

固定HD1910配置为 `kp_fw=5`、`vin_range=(7.4,8.0)`、`vin_min=7.0`、负载压降增益范围 `(0,0.2)`、延迟3–6个仿真步。它们是训练配置，不能直接当成舵机寄存器写入表或整机电气验收值。

`robot/hd1910/README.md`明确：参数采用LuwuDynamics公开结果；原始辨识数据、测试电压与固件未随参数记录提供。`q_offset`不是本机零位；`max_velocity=100`也不是舵机实际空载速度。

### 已找到的具体适配缺口

| 文件 | 静态发现 | 对本机的影响 |
|---|---|---|
| `scripts/validate_bam_testbench.py` 第22–24行 | 指向 `~/Rhoban/bam`、processed数据和XL330的 `m6_new.json` | 仅安装当前锁定依赖，不代表这份数据与路径已具备 |
| `scripts/testbench_sim2real.py` 第18–19、116–135行 | 单关节4维观测、1维动作，加载XL330 M6并使用XL330执行器 | 不能作为整机61维/14维HD1910部署测试 |
| `scripts/infer_policy.py` 第884–895行附近 | 普通MuJoCo位置执行器，电流限幅路径使用XL330参数 | 外观能走也不能证明匹配1910 BAM电压/摩擦动态 |

这些是可复用参考，不应删除；后续用单独HD1910配置或脚本适配，避免改坏上游XL330基线。

### 若以后要完成本机辨识

1. 先形成能可靠读回和卸力的单关节台架，固定固件、寄存器、电压、温度与负载。
2. 记录命令位置、编码器位置/速度、时间戳、真实供电及可信电流字段；电流单位未验证前不得当作安培。
3. 在明确限位与限幅下设计激励，区分命令延迟、摩擦、死区/齿隙和负载效应。
4. 将数据拆为拟合与留出验证，保存公开M6基线与本机拟合结果的轨迹误差对比。
5. 单独检查不同方向、速度、负载与电压，记录有效范围；通过后才把新参数接入本机实验任务。
6. 最后验证整机闭环，不用单关节拟合误差替代行走、停止和恢复能力。

这是后续实验需求，本轮没有执行或修改参数。

### 环境与训练应如何验收

1. 在独立工作副本安装锁定依赖，记录Python、GPU、驱动、锁文件和包版本。
2. 枚举真实任务、加载匹配MJCF，检查关节、碰撞和执行器；先小规模短测。
3. 64环境、5轮一类短测用于确认链路与日志，不是行走策略已训练完成。
4. 固定任务、配置、随机种子、源码和输出目录，再开始正式训练；环境数由显存实测决定。
5. 保存完整PT、配置、优化器等可用状态、曲线、视频及失败场景；评估不能只看reward。
6. 倒地恢复需单列不同初始姿态和恢复标准。`standup`文件开头主要描述坐姿→站姿，不能凭名字代替任意倒地训练任务。

Training Studio演示模式生成合成指标和示意资源；真实模式才调用训练引擎。暂停可能保留显存；关闭服务与关闭浏览器行为不同。迁移应保留 `training-studio/state/runs/` 和 `training/logs/rsl_rl/`，不能只下载一个视频。

### 整理者需要给出可执行的补法

1. 明确当前引擎检查点与任务如何生成同次导出的 `manifest.json` 和 `deployment-contract.json`。
2. 如复用历史training-console导出器，记录适配文件、任务、依赖和输入，验证与当前mjlab版本相容；不能只把入口链接过去。

5. 执行同观测PT↔ONNX输出对比、合同校验和本机runtime预检，保存成功与失败结果。
6. 以一个真实HD1910小实验走通“PT→ONNX→完整部署包→预检”，再将指南写成已经可执行的步骤。
