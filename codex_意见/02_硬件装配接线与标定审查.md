## 双IMU到底表示什么

| 位置 | 可能硬件 | 主要作用 | 本机判断 |
|---|---|---|---|
| 头部HAT上 | C1的BMI088或D1的LSM6DSV16X等 | 头部传感，取决于服务是否启用 | 看具体HAT，不能提前保证板上一定是哪颗 |
| 躯干固定板 | 总线IMU中的LSM6DSV16X，或受支持I²C模块 | 行走所需机身姿态与角速度 | 需要独立于头部的位置与正确方向标定 |

如果最终HAT带头部IMU、又安装躯干IMU，物理上可以是两颗IMU。**这不等于策略将两颗IMU融合成双重冗余定位。** 配套runtime文档中 `[head_imu]` 默认关闭；躯干后端单独选择。已购两笔BMI160也不代表当前“双IMU”已配齐。

固定runtime的[支持说明](../02_feetech/Microduck-kissqy_runtime_20261023c/IMU-MODULE.md)列出 `bus`、`bno08x`、`lsm6dsv16x`，未把BMI160列为可直接替换项。I²C接口相同不能推出驱动、姿态数据、地址和电气兼容。

## 电控方案尚未冻结的具体问题

### 1. 板卡名不能替代修订和固件

| 资料分支 | 已有材料 | 不能省略的区分 |
|---|---|---|
| fanhao旧版imu_to_dxl设计 | EDA、原理图、接线表、交互BOM、源码与HEX | 板的实物状态与固件实测是不同证据 |
| fanhao固件0.2.0与1.0.0 | 有各自说明；1.0.0有舵机共线局部测试记录 | 两版不等于整机长期通过；调试观察器和排队处理有差异 |
| kissqy FT6固件 | 配套runtime、固件源码/二进制与协议说明 | 对硬件、身份、快速读块及Sync Read顺序有自身约定 |
| fanhao新版三板 | IMU、wire_hub、POGO工程及STEP | 作者注明未完整打样验证；新Gerber/BOM/接线表尚未发布 |
| community-kit的板 | banana PCB生产资料等 | 同项目中的其他MCU/IMU设计不能自动套用STM32 FT6固件 |

**特别需要整理者标明的差异：** fanhao旧IMU README对某版固件描述了ID200排在舵机后面的实测；kissqy FT6说明要求ID200在Sync Read列表首位，并明确不要移植其他排队逻辑。不能只因两者都叫“ID200、15字节”便混用。应记录板卡、固件哈希和运行端的实际组合，再执行配套总线验收。这是跨分支差异，不能据文字差异直接判定当前镜像存在故障。

依据：[fanhao IMU说明](../02_feetech/microduck-replica_20261024/hardware/imu_to_dxl/README.md)、[FT6说明](../02_feetech/Microduck-kissqy_runtime_20261023c/microduck-hd1910/firmware/firmware/imu-source/README_FT6_SYNC15.md)、[新版硬件状态](../02_feetech/microduck-replica_20261024/hardware/新版/README.md)。

### 2. 最终接线表至少应有这些字段

| 对象 | 必须记录 |
|---|---|
| 每块板 | 正反面照片、修订、连接器名称、安装方向 |
| 每根线 | 起点端口/针号 → 信号 → 终点端口/针号，长度、线规、端子和是否交叉 |
| 供电 | 电池端、舵机支路、主控稳定5V支路、共地、保护与断开位置 |
| 总线 | DATA/GND/V的逐针关系、电平、波特率、协议、舵机与IMU身份 |
| IMU | 总线后端或I²C地址、传感器轴、安装旋转、读数与新鲜度验证 |
| 相机/音频/ToF | 接口、针序、供电、排线方向、驱动和设备路径的实际读回 |

现有功能框图说明“谁连谁”，还没有覆盖本机最终逐针接法。AMP2.0、5264、PH等商品名称和红黑线色都不能替代针序核对。

### 3. 首次供电仍缺实测

1. 断电核对电池触点、banana板、导线、正负极、绝缘和固定。
2. 分开识别电池原压、舵机电源和主控5V。按实物铭牌测量，不能把全机统一当6V或让电池原压直入ZERO。
3. 台架先验证稳定5V及主控启动，再按最终板卡方案逐步接入负载，记录压降、温升和重启现象。
4. Adapter A无稳压，既有厂家资料有5A承载边界；不能把单舵机调试接法直接扩大成15舵机整机供电方案。
5. 整机在承托条件下先验证读数与卸力，再允许承重；保留能立即切断异常供电的操作位置。

没有本机电流与压降数据，不在报告中估算“15颗舵机肯定需要多少安”或保证现有电池满足全部动作。

## 装配资料有了，现场还要做什么

| 工序 | 已有资料 | 需要落实的事项 |
|---|---|---|
| 清点与分组件 | 作者BOM、组件图、装配PDF | 套装与补购件避免重复计数；轴承大11小3已确认 |
| 舵机入结构前 | 编号表与工具 | 先单颗读回、配置、断电重读和贴标签，再串接 |
| 腿、髋、躯干 | PDF、视频与实物图 | 左右以机器人自身为准；轴承同轴、舵盘方向与螺丝长度 |
| 躯干与髋紧固 | 作者补充截图 | 指定位置使用合适长度M3机螺丝，不以已买的自攻螺丝替代 |
| 颈部走线 | 组件图/视频 | 转动不拉紧、无夹线、预留弯曲与维修空间 |
| 头部安装 | 主控/HAT/相机/音频资料 | 排针高度、FPC弯折、镜头突出量、麦孔与扬声器固定 |
| 触点安装 | banana板和插头资料 | 插拔、极性、抗松脱和线束应力，不能仅确认板能塞入 |
| 足底 | 防滑垫与模型接触面 | 厚度、平整度、软硬和摩擦会改变实机行为 |
| 零位支架 | STEP与作者两张照片 | 作者只验证了下半部；不能把未验证的上半部当精确标定夹具 |

现有21页装配PDF没有每颗螺丝长度和全部走线。缺少的数据应实测补表，不能由整理AI按图片猜尺寸。打印件已获用户确认，不重复质疑购买版本；装配行程、间隙与实物碰撞仍需检查。

## 零位标定必须分清的四件事

| 名称 | 含义 | 常见混淆 |
|---|---|---|
| 编码器零点 `zero_raw` | 该颗实物舵机在机械基准姿态的编码器读数 | 把模板2048或作者机器的数值直接复制 |
| 关节正方向 `direction` | 编码器增量与模型正向的映射 | 按左右对称推测正负而不做小动作 |
| 策略HOME | 模型站姿，通常弯腿和抬颈 | 将站姿当作全部关节0 rad |
| 执行器模型 `q_offset` | BAM参数中的辨识偏置 | 写进逐关节实机零位，造成重复偏置 |

1. 固定ID和实际部位；对照机械基准摆位。
2. 按Studio逐颗记录/校准，并进行小幅正负方向验证；不能仅看网页三维动画。
3. 检查实物可达限位、外壳和线束，不把模型限位当实机已测值。
4. 固定躯干IMU，验证静止和前后左右倾斜的方向及角速度。
5. 写入主程序后重启核对实际生效文件，再在承托下验证HOME与卸力。
6. 建立本机标定备份，记录文件哈希、日期、舵机更换情况。换舵机或机械重装后重新核查受影响项。

当前[验收模板](../00_notes/03_标定与验收记录模板.md)仍全是待填。模板最后的 `jaw` 与当前标定文件 `mouth` 命名不同，应在整理时统一或明确映射；不能据此多算一个关节。

## 首走到恢复动作的验收关卡

| 关卡 | 通过条件 | 失败后回到哪里 |
|---|---|---|
| 读数 | 15舵机身份唯一，IMU有新数据 | 单颗配置、针序、供电与协议 |
| 标定 | 零位、方向、限位和IMU对应实物 | 机械装配与标定 |
| 承托上力 | HOME方向正确，无顶限位，能立即卸力 | 标定、增益和机械检查 |
| 手柄急停 | 实际上力后Select短按松开能卸力；网页也可卸力 | 手柄模式/映射和状态机 |
| 落地保持 | 平地静止与停止可重复完成 | 供电、足底、模型和姿态 |
| 低速首走 | 小幅前后、转向、停止及失联处理有记录 | 保留诊断包，恢复基线 |
| 普通脚底恢复 | 分别记录起始倒姿、地面、恢复时间与失败 | 单独分析，不用反复摔落代替验收 |
| 扩展并发 | 相机/音频/ToF运行时运动与供电仍稳定 | 模块逐个回退定位 |

坐站模型不代表任意倒地恢复；轮滑起身不适用于普通脚底。Select长按约2秒的坐下卸力关机，与短按急停需要分别核对。上述本机测试本轮均未执行。
