### B. 现在先做什么

1. 等待已发货的 ZERO 3W 到货，核对 1GB、无 eMMC、排针及 PCB/Wi-Fi 批次，V1.12J 线索见 K115；不重复采购主控。
2. 对照当前装配照片检查关节活动、螺丝、走线和承托；照片不能证明已完成编号、归中或标定。
3. 用 Bus Servo Adapter (A) 核对 15 颗舵机 ID 并保存读回结果，ID 见 [02 指南 D1](00_notes/02_分阶段复现指南.md)。
4. 核对已到手 IMU 的板号、方向与固件，以及 HAT/HUB 的到货与接口；未核实前不沿用其他板型的安装和接线参数。
5. 补打件按 BOM 的 2026-11-10 计划处理；普通脚底首走与滑轮鞋作为不同机械配置分别验收。

装配到首走的顺序：机械装配 → 电控装入但**不封头壳** → 写卡、首次通电，只确认网页可进、IMU 被识别、15 颗舵机扫到 → 封壳 → 网页清单（零位、IMU 方向、写入、手柄、急停）→ 低速首走 → 整卡备份。依据见 K115。

#### 作者仓库与 VS Code 拉取

| 仓库 | 打开位置 | 分支与远程 |
|---|---|---|
| 本机整理仓库 | 项目根目录 | `main`；`xlx2730109-code/Microduck` |
| fanhao 作者主仓 | [07_upstream/fanhao375/microduck-replica](07_upstream/fanhao375/microduck-replica/) | `master`；`fanhao375/microduck-replica` |

`07_upstream` 只保存 `作者名/仓库名` 结构的作者仓库。额外更新脚本已删除，作者仓库中的 `.git` 保留；原有历史快照继续在原处，不改本机固定复现版本。

1. VS Code 选择“文件 → 新建窗口”，再选“文件 → 打开文件夹”，打开上表的作者主仓目录。
2. 按 `Ctrl+Shift+G` 打开源代码管理，确认当前仓库是 `microduck-replica`，分支是 `master`。
3. 在源代码管理的 `…` 菜单选择“拉取 / Pull”。该仓库已设置跟踪 `origin/master`，并配置只允许快进更新。
4. 后续可从 VS Code 的“打开最近的项目”再次打开这个作者目录，然后执行拉取。

若希望在同一窗口查看多个仓库，可用“文件 → 将文件夹添加到工作区”加入作者主仓；操作前在源代码管理的仓库列表选中作者仓库。仅在根目录展开作者文件夹，不代表 Git 操作已切换到作者仓库。

在根项目的 VS Code 终端中，也可明确指定作者仓库拉取：

```powershell
git -C .\07_upstream\fanhao375\microduck-replica pull --ff-only
```

“同步更改”包含先拉取、再推送；只获取作者更新时选择“拉取”。`git pull` 仅更新仓库跟踪的文件，不自动下载 Release 镜像、CAD 压缩包或其他仓库。操作依据：[VS Code 仓库与远程说明](https://code.visualstudio.com/docs/sourcecontrol/repos-remotes)。

# 08_local_web
目标：电脑登录后自动提供两个 Microduck 本地演示网页，并在进程异常退出后恢复服务。

## 基准与结论

### A. 入口与运行方式

| 对象 | 入口 | 作用 |
|---|---|---|
| 舵机调试台 | http://127.0.0.1:8080/ | 模拟舵机及3D调试展示 |
| Studio | http://127.0.0.1:18080/ | 使用模拟机器人后端 |
| 手动启动 | `08_local_web/Start-Microduck.cmd` | 启动已注册的计划任务 |
| Windows任务 | `Microduck-Local-Web` | 当前用户登录自启，每分钟补启动，运行中忽略重复实例 |
| 运行日志 | `08_local_web/logs/` | `supervisor.log`记录退出、恢复与进程号 |

- **08-K1**：用户于2026-11-10明确确认设置自启；长期服务位于本目录，含独立Python 3.12.14，不依赖旧临时目录或Codex运行时缓存。原机器人源码、CAD和系统镜像未改动。
- **08-K2**：任务以当前用户普通权限后台运行，无执行时限；电池模式允许启动且不终止。网页服务只监听本机回环地址。仍为演示模式，不表示已连接实体机器人。
- **08-K3**：网页子进程退出或连续三次HTTP检查失败时，守护程序重启演示进程；守护程序本身停止后，每分钟的任务触发器负责补启动。单独配置Windows失败重试在本机强制退出测试中未触发，因此不能只依赖该设置。
- **08-K4**：子进程归入带`KILL_ON_JOB_CLOSE`的Windows Job，守护程序被强制结束时一并清理，避免遗留进程占端口。机制依据：[Microsoft Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)。

### C. 手动管理

需要手动启动时双击上表中的启动入口。停用自启时先禁用任务，再结束任务，否则补启动触发器可能重新启动服务。

禁用自动启动：

```powershell
Disable-ScheduledTask -TaskName 'Microduck-Local-Web'
```

停止当前服务：

```powershell
Stop-ScheduledTask -TaskName 'Microduck-Local-Web'
```

重新启用自动启动：

```powershell
Enable-ScheduledTask -TaskName 'Microduck-Local-Web'
```
